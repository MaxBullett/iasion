# Release 1: Manual ledger

Status: defined. Stories reviewed in the [R1 event storming](../event-storming/r1.md);
enablers decided in ADR-0033 to ADR-0040, except the walking skeleton, which is built
from them.

## Goal

A household can capture its accounts, opening balances and flows by hand and see an
honest picture of the present: what it owns, where money comes from and where it goes.

R1 is also the walking skeleton. It sets up the infrastructure, the agent workflow and
the first end-to-end slice that later slices copy.

## Done when

- The maintainers have captured their own household's accounts (including cash wallets)
  with opening balances and at least one month of flows.
- The balance sheet and the in/out view show figures they recognise, and every
  checkpoint difference can be explained.
- It runs on a self-hosted instance behind Cloudflare Access, deployed from CI.

## In scope

| Area | Scope | Stories |
|---|---|---|
| Household | Members, boundary, counterparties including aggregate parties | S-001, S-002 |
| Accounts | Owners, ownership shares, optional institution (cash wallets per member) | S-003 |
| Starting point | One opening balance per account | S-004 |
| Flows | Manual entry of income, spending and transfers between own accounts, individual or aggregate | S-005 to S-007 |
| Corrections | Correcting or voiding a recorded flow; correcting parties, accounts, ownership shares and purposes. Append-only. | S-008, S-015 |
| Classification | One user-defined purpose vocabulary, manual assignment | S-009, S-010 |
| Checkpoints | Record an observed balance, show the difference. Nothing is booked. | S-011 |
| Views | Balance sheet as of a date; in/out by purpose over a period; an account's transactions over a period | S-012, S-013, S-016 |
| Access | Sign in via Cloudflare Access; login identities map to members; first setup by the email named in the environment | S-001, S-014 |

Stories and acceptance criteria: [story-map.md](../story-map.md#stories).

## Out of scope

Deferred to R2:

- Import of any kind (CSV upload, Iasion API ingestion, bank connections)
- Resolving checkpoint differences: suspense party and suspense booking
- Coverage intervals
- Deduplication and transfer matching (only needed once imports exist)

Later:

- Search across transactions and accounts
- Contracts, generators, series, projections, strategies
- Suggested classification, dimensions other than purpose, pools, budgets
- Valuations and non-currency units
- Multi-currency. R1 is EUR only.
- Archiving: closing an account, a member leaving, retiring a purpose (OQ-042)
- A backfill feature (import, gap detection) for the time before an account's opening
  balance. R1 does not prevent moving an opening balance to an earlier date and
  entering the flows in between by hand (ADR-0015).
- Documents

## Constraints

- **Single currency:** every position and flow in R1 is in EUR, the reporting currency.
- **Bitemporal from day one:** every ledger fact carries valid time and recorded time, even
  though R1 has no UI for recorded time. Retrofitting recorded time later would mean
  migrating every fact table.
- **Append-only:** no fact is updated or deleted in place (see S-008).
- **Kernel stays plugin-free:** nothing in R1 is jurisdiction-specific.
- R1 implements only part of ADR-0007 (accepted): the opening balance and a
  display-only checkpoint. Suspense booking, coverage intervals and fitting on
  incomplete data come in later releases.

## Enablers

Technical work without its own user story. Each decision gets an ADR before
implementation.

| Enabler | Decision so far | ADR |
|---|---|---|
| Persistence | PostgreSQL 18 only; one schema per context; versioned facts in append-only tables; sqlx; forward-only migrations | [ADR-0033](../adr/0033-persistence-postgresql-versioned-facts.md) |

| Repo and workspace layout | One repository; one crate per context with persistence behind a `postgres` feature; dependency edges checked against the context map | [ADR-0034](../adr/0034-workspace-layout.md) |

Betterleaks in hooks and CI; GitHub secret scanning and push protection. | [ADR-0039](../adr/0039-ci-and-secret-scanning.md), AGENTS.md (Personal data and secrets) |
